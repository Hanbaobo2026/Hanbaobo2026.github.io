ShadowLedger

ShadowLedger is a KVM-subsystem kernel pwn challenge. Inside the guest you
are a nobody tenant; the goal is to become root inside the guest and read
/flag. The full scenario and the helper-tool notes are in
shadowctl_usage.md.

Requirements

  • x86-64 Linux with Docker
  • /dev/kvm on the host and nested virtualization enabled (the guest
    creates its own VMs)
  • nc
  • Python 3 (for upload.py)

Local Docker

docker build -t shadowledger .
docker run -d --name shadowledger -p 1337:1337 --device /dev/kvm shadowledger
nc 127.0.0.1 1337

Each TCP connection gets a fresh guest; a connection is limited to 600
seconds. The local /flag is flag{test}.

Host QEMU

./run.sh

Send a payload

The guest has no network and no compiler, so the payload must be a static
binary:

gcc -static -O2 -o exp exp.c
python3 upload.py 127.0.0.1 1337 ./exp

The script uses the guest’s built-in upload helper (base64 + gzip over
the serial line), writes /tmp/exp, and runs it.

Manual alternative inside the guest shell:

upload
# paste base64(gzip(exp)), at most 512 chars per line, end with: EOF
/tmp/exp

Upload and run in the same connection: every connection is a fresh guest.

Notes

  • The guest /flag is root:0400; the exploit must obtain root.
  • shadowctl help / shadowctl demo show the ordinary audit path. The
    demo is a one-VM negative test and is expected to hit the role gates.

shadowctl usage

Scenario

ShadowLedger is a settlement ledger for private-memory receipts on a
multi-tenant KVM host. A tenant publishes a receipt for a private page, and
the receipt only becomes final after the other tenants witness, co-sign,
settle, accept, and fold it. The ledger records each step as an entry and
keeps the roles separate, so no single tenant can complete a transfer on
its own.

Inside the guest you are given /dev/kvm and /usr/bin/shadowctl.
Goal: break out of the tenant context and read /flag.

The ledger is exposed on KVM VM fds; the VM is intentionally minimal.

Commands

Notes

demo opens one VM and files a short sequence itself. Some steps are
rejected by design; that is expected. The demo only illustrates the
interface and never escalates privileges.

ShadowLedger windows include publish, certify, co-sign, settle, accept,
fold, renew and revoke. The helper is a reference for part of the ioctl
surface, nothing more.
