crp 题（魔改 AES-192 + 多素数 RSA）交接文档

更新：2026-11-01。旧实例 x.x.x.x:39001 已下线；新实例 x.x.x.x:20596 已验证在线（2026-11-01）。
附件 chall/N.txt/hint.txt 与旧实例完全相同（chall MD5: c989394fbf0fd2c5c280c016f28178e8）。
注意：TARGET_CT 每实例不同 → flag 按实例生成；N 与 e 固定。

一、题目与攻击面

  • 附件：chall（x86-64 ELF，未 strip）+ N.txt（1248bit）+ hint.txt（gylike{魔法仕掛けのファンタジア}，44 字节，maimai 歌名）
  • 菜单服务：
    • [1] TARGET_CT = flag^65537 mod N（教科书 RSA，单次计算、跨连接恒定）
    • [2] AES-ECB 单块加密 oracle，输入 32 hex，每连接预算 2500 次（0x9C4）
    • [3] H1NT_CT = AES-ECB(hint + PKCS7)，48 字节 3 块（长度与已知 hint 完全吻合）
  • 提示 1248=272+704+272 → N = p·q·r，素数位数 272/704/272

二、二进制逻辑（Ghidra 反编译 + 汇编级确认 + 远程实测吻合，置信度高）

魔改 AES-192（每连接随机）

  • S 盒被篡改 1 项：init(seed) 构造标准 AES S 盒复制到 SBOXXX，bugf() 用 MT19937(urandom 32bit seed) 出两个不同字节 i,j，设 SBOXXX[i]=S[j] → 非双射：值 S[i] 不可达，S[j] 有两个原像
  • 密钥 24 字节每会话随机（random_device→MT19937）；rk0=key[0:16]；末层 fk = key[16:24]||key[16:24]（8 字节重复，汇编已确认两处都从 +0x10 加载）
  • 轮密钥链（12 轮）：rk_{k+1} = MixColumns(ShiftRows(S'(rk_k ⊕ ShiftRows(rk_k) ⊕ RCON[k])))，RCON 为标准表但 XOR 到全部 16 字节
  • 加密：st=pt⊕rk0; for r=1..12: [r≠12: MixColumns]→ShiftRows→SubBytes→⊕rk_r; ct=st⊕fk
  • 注意轮序是 MC→SR→SB→ARK（非常规），最后一轮无 MC
  • shift_rows 的索引映射（非标准解释但按伪代码逐位复现）：out[r*4+c] = in[c + ((r+c)%4)*4]；mix_columns 是标准 [2,3,1,1] 矩阵
  • 纯 Python 完整复现已自测通过：E:\ctf-workspace\challs\crp\aes_core.py（SimOracle 也在此目录）

RSA 部分

  • 教科书左到右模幂，e=65537 写死，mul_big/mod_big/cmp_big 全部标准（调用点寄存器传参已反汇编逐个核实）
  • flag 转大整数需 < N（有检查，否则 [1] 报错）

三、攻击研究结论

已验证成立的关键结构（核心资产）

  1. 直线碰撞读 d（确定性！）：令 Lmap(t,c) = MC⁻¹(SR⁻¹(c@t))（c@t 表示 16 字节向量仅字节 t 为 c），则查询直线 {P0 ⊕ Lmap(t,u) : u ∈ 0..255}（256 次）时，第 1 轮 S 盒输入在字节 t 上 = u ⊕ const 遍历全部 256 值各一次 → 恰好 1 对密文碰撞 {u*, u*⊕d}，直接读出 d = i⊕j。远程 3 会话实测全部命中，每线恰好 1 事件。
  2. 每条直线事件给 K0 的 8 个 GF(2) 线性约束：[SRMC(K0)]_t = SRMC(P0_t)_t ⊕ (i 或 j)（β/d 技巧吸收二选一，i 也可作全局未知量进线性系统）
  3. fk=M||M 给 64 bit：rk12[p]⊕rk12[p+8] = T[p]⊕T[p+8]，p=0..7，其中 T[pos]=rk12[pos]⊕fk[pos] 可由统计获得（见下）
  4. 末轮统计指纹（2500 样本）：ct[pos] = SB(x12[pos]) ⊕ T[pos]，每个位置恰好 2 个结构性零值（v*⊕T[pos] 与 S(μ_t)⊕T[pos]，其中 μ_t = v*⊕rk11[SIG[t]]，因第 11 轮 S 盒输出同样缺 v*），254 个 distinct，1 个双频值 vj⊕T[pos]（约 2× 频率）
  5. 统计退化定理（重要，避免踩坑）：(v*, vj, T) 整体 XOR 平移 δ 后统计完全等价 → 统计只能得 dv = v*⊕vj；结合直线读出的 d，扫 256 个 i 可唯一解出 (i,j)：S[i]⊕S[j]=dv 且 i⊕j=d

完整攻击方案（信息量 136 > 128，唯一确定 K0）

  • 9 条直线（2304 次）→ d + 72 bit 线性约束 + 每线 1 事件
  • 196 次随机查询（凑满 2500）→ 统计：dv 投票（每位置 top-6 频值 × 2 零值交叉投票）→ (i,j)；2 零值歧义用每位置 1 个选择器变量（β/d 同款技巧）编码进 M-关系
  • SAT 求解 K0：调度链（12 轮 × 16 S 盒 = 192 个 S 盒真值表）+ M-关系 + 9 组直线方程
  • 解出后：T 直接由 T = ct ⊕ state12(pt; K0) 计算（无歧义）；用 50 个 oracle 对验证；解密 H1NT_CT（SB⁻¹ 在双频值处分支，非可打印剪枝）

已排除的死路（别重复）

  • ball/超立方碰撞采集：结构化 ball 内所有点的 x_b 只取 2 个值 → 碰撞全有或全无（~12%/ball），无效
  • XOR 统计恢复 T：XOR 是双射，”缺失值个数”不随猜测变化，只能从缺失值的”身份”入手
  • 多会话累计：密钥+S 盒每会话随机（直线事件候选集跨会话不相交，已实测）
  • RSA 侧全灭：p−1（B1=10^7 全素数幂含 2^n 阶梯）、p+1 Williams、ROCA 指纹（p=11 即可排除）、二进制常量 gcd（S 盒/逆 S 盒/RCON/GMUL 表/hint 切片共 811 个候选）、FactorDB（未收录，status C）、TARGET_CT 完全幂（e=2..65537）
  • 82 位十进制因子接近 ECM 世界纪录 → 若 flag 只在 RSA 里且无新结构则基本无解

当前卡点（交接重点）

  • SAT 规模：393,216 子句（S 盒 2048 子句/个 × 192）+ 3208 条 XOR
  • pycryptosat (CryptoMinisat)：一次性 bootstrap 39 万子句崩 ERROR: while reallocating clause space；分批 add_clause 的方案写了但没来得及验证完（被中断）
  • Tseitin-XOR + Cadical153：单候选（真值，SAT 方向）跑 25 分钟未出 → 太慢
  • 建议方向：
    1. 修 cms：分批加子句 / 或换原生 cms 二进制（本机 Windows 没有）；
    2. 砍子句数：用文献里的紧凑 AES S 盒 CNF（~200 子句/盒，总子句降到 ~5 万），或把 S 盒编码成 affine∘inv∘affine 电路 + 单点修正 mux（dv 已知）；
    3. (i,j) 候选按 dv 票数排序（本次 sim 出了 4-8 个候选，每个都要解一次 SAT，UNSAT 方向可能更慢）；
    4. 编码已单元测试通过的部分别动：调度链 CNF 与真值一致（schedule_chain 已验证 rk12 逐位正确）

决定性悬而未决问题

  • H1NT_CT 解密结果是 flag 还是已知 hint 串？ 若服务端 HINTFILE=flag（题面”提取 AES 密钥解密出 flag”暗示此方向），AES 攻击成功即赢；若解出已知 hint，则 flag 在 RSA 里，需分解 N（当前无路）
