babysilent 解题/调试指南

0. 先说明结论

  • 远程真实 flag 还没有拿到。
  • 本地已经验证成功的部分：canary/PIE 泄露、栈溢出、seccomp 下的 ROP、gets 栈迁移、逐字节阈值 oracle。
  • 还没完成的部分：远程 wrapper 直接 execl("./pwn")，PIE 和 libc 基址没有固定关系，当前脚本里 libc = pie - 0x3f1000 只适用于本地 ld --library-path 启动方式。
  • 因此现在运行 remote_gets_oracle.py 不会得到真实 flag，只会看到探测结果。

预期输出类似：

含义：

  • flag[0] = 'F' = 0x46 = 70
  • C=69：V >= C，第二个 read(0, buf2, 1) 阻塞，进程还活着。
  • C=70：V >= C，同上。
  • C=71：V < C，第一次 read 留下 1 个字节，第二次 read 把它读掉后进程退出。

这就是逐字节泄露 flag 的 oracle。

该脚本会：

  1. 连接远程；
  2. 用长度 89 泄露 canary + PIE；
  3. 用 libc = pie - 0x3f1000 计算 libc；
  4. 发送 stage1 和 chain。

注意：第 3 步在远程是错的。 远程直接执行 pwn，PIE 在 0x55...，libc 在 0x7f...，两者没有固定偏移。

6. 下一步要写的代码（拿真实 flag 的路线）

路线 A：ret2dlresolve（推荐）

  1. 保留长度 89 的 canary + PIE 泄露。
  2. 第二输入构造 stage1：
    • 正确 canary；
    • 利用 read@plt + 栈上的 printf 缓冲区做大 read；
    • 在覆盖后的栈上放一条 PIE-only 的 ROP 链。
  3. 用 ret2dlresolve 解析 gets / read。
  4. 用 gets 或 read 把第二阶段链读进 PIE bss。
  5. 用 read(3, flagbuf, 0x100) 读 flag。
  6. 用 read(0, buf, flag_byte) + 第二次 read(0, buf2, 1) 做逐字节 oracle。
  7. 通过 wrapper 的 EPIPE/阻塞行为判断阈值，二分出每个字节。

路线 B：先泄露 libc

需要找到一次 printf 同时拿到 canary 和 libc 的方法，目前没有完成。

7. 重要提醒

  • /tmp/babytest/flag 里的内容是本地测试 flag，不是远程真实 flag。
  • 不要把本地测试 flag 当成题目答案提交。
  • 远程自动化脚本每次连接都会重新随机化 PIE/libc/canary，不能跨连接复用地址。
  • remote_gets_oracle.py 目前只是调试/探测，不要直接期望它输出 flag。
